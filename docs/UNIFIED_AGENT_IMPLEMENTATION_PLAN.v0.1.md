## 2. 关键接口与实施边界

- **统一入口。** 从 `connect/core-contract.mjs` 演进 `InteractionEvent`，并为现有 QQ、iLink、桌面入口提供转换。事件携带渠道、账号、来源事件 ID、会话、发送人、接收时间、范围和 `trace_id`。接入去重以渠道、账号、会话及稳定来源 ID 为边界。重投沿用原追踪，入站原文由渠道存储管理，审计保留引用和必要摘要。
- **共享身份与认知。** 基础人格继续由 Brain 加载，渠道只提供语体和交付格式。会话按渠道、账号及会话类型隔离，人物映射用于共享经过授权的记忆。路由返回处理模式、目标、所需能力、风险和追问原因。明确闲聊直接响应，单能力直接路由，多步骤目标进入规划，平台事件走专用处理器，自主事件在 P2 接入。
- **能力与规划。** 能力索引作为发现入口，沿用现有能力 ID，按试点逐项补 Manifest。首批字段包含输入输出、版本、状态、权限、绑定工具及验证要求。Planner 输出能力 ID 和参数，能力执行层校验并调用工具。模型侧的源码读取在首期从普通交互工具表移除，工程排查使用现有本地接口。
- **权限与审批。** 在上下文组装前限定数据范围，在实际执行前以已经验证的身份、会话、能力和目标再检查一次。首期沿用现有外发权限，建立 R0–R4 映射。草稿审批绑定任务编号，发布复审绑定账号、草稿版本、操作、审批者和有效期。保留现有 QQ 与看板入口；只有一个上下文匹配的待办时兼容快捷确认，多待办时要求编号。内容或目标变化后重新确认。
- **任务与证据。** `external_tasks` 继续负责对外任务状态，`working_tasks` 提供恢复视图，步骤以任务和步骤 ID 持久化。沿用 `receipts`、`skill_runs` 及 `agent_events`，把已经调用、平台接受、业务已验证分开记录。已授权的外部步骤以任务、步骤、账号和目标锁定一次动作；超时或送达不明先读回平台状态，再依据证据决定恢复方式。仅独立只读步骤允许并行，涉及同一手机或发布会话的步骤串行。
- **部署与数据。** 保留 Brain 和 Connect 的现有进程入口及三个库。变更初期以可空字段、索引和新增记录兼容旧读写。用 `trace_id` 关联不同库，任务终态以 Connect 记录为准，作品和评论证据引用抖音库。各服务按渠道开关切换到新路径。

## 3. 实施顺序和验收门槛

| 里程碑 | 交付范围 | 验收门槛 |
| --- | --- | --- |
| **P0-A · 基线、契约与权限** | 为现有工作区建立可重现基线；固定事件、身份、会话、路由与审计契约；实现策略校验、读记忆的范围过滤及追踪 ID。QQ 私聊先以旁路计算新路由并记录差异，副作用仍由现有路径执行。 | 同一条入站消息的重投只产生一次有效决策；缺少上游 ID 有明确降级；群成员和微信好友的测试请求无法读取主人记忆或批准主人任务；旧版本样本库可迁移，迁移后既有记录可读。 |
| **P0-B · QQ 私聊首条主链路** | 在 QQ 私聊切换到共享 Runtime。覆盖闲聊、单项查询、复杂只读任务与写任务提案；抽出 QQ Planner 的通用步骤校验及事实回灌。首批能力包括作品数据查询、草稿和发布。用现有看板展示一条请求的路由、审批、执行及结果。 | 闲聊不建任务；单项查询给出数据来源和范围；多步骤分析按依赖执行；发布保留两阶段审批，重复投递、并发确认、超时、进程中断都不重复触发动作；只有平台读回证据匹配账号和作品才标记发布成功。 |
| **P0-C · 执行收口与第二入口** | 在首批任务落地步骤依赖、暂停、恢复、取消、超时和部分完成；合作式取消在安全检查点处理。桌面接入同一事件与路由契约；微信文字、语音和好友隔离先用回放对照，达到门槛后单独切换。QQ 群沿用现有上下文和审批限制，迁入同一策略判断。 | 只读依赖失败会阻断下游步骤，暂停后保留已核验结果；中断的外部动作进入待核验；桌面与 QQ 回放相同只读目标时选用同一能力；语音回退行为与群聊权限的既有用例通过。 |
| **P1-A · 抖音评论专用流程与记忆检索** | 让 `reply-inbox`、`hot-comments` 复用评论理解、范围过滤和回复策略，沿用 `compliance`。先跑样本与只生成建议模式，再按现有授权接入发送。用统一查询入口覆盖七类记忆、来源与范围，扩展人物、作品、任务、能力关联及事实修正。 | 普通评论走专用处理，复杂请求形成候选；公开回答只检索可公开记录；缺少可靠评论 ID 时保守匹配，冲突转人工；编辑框关闭记为待核验；旧记录通过兼容查询仍可访问且符合访问范围。 |
| **P1-B · 学习验证闭环** | Academy 管课程和训练，技能层管能力版本与运行记录。以评论意图和回复策略做首个领域试点，关联样本、基准、候选版本、对照结果和启用审批。 | 课程通过后生成学习证据；候选版本达标并经授权后启用；回滚后后续任务选择原稳定版本，历史运行仍能追溯使用版本。 |
| **P2 · 自主目标与渠道扩展** | 统一日程、生活任务和目标的入口，复用现有预算、静默时段和排期。用户任务优先，情绪参与表达与排期建议。扩展微信、桌面语音和 Companion 的已验证场景，未来机器人预留适配器契约。 | 自主触发受预算和权限控制，主动任务可暂停；微信或手机新增交互可复用同一人格、范围检查、路由和执行层。 |

串行依赖为 P0-A → P0-B → P0-C。P1-A 与 P1-B 共享已稳定的能力和证据接口，其中评论策略的线上试验依赖 P1-A 的核验路径。首期按三个可逐步合入的变更批次审阅，工期在核实设备验证和迁移样本后再排定。

## 4. 验证、发布与回退

- **每批回归**运行 `npm test` 和 `node scripts/capabilities.mjs --check`。沿用 `scripts/intent-regress.mjs` 的样本，先用可复现的模拟模型测试路由和越权边界，真模型单独跑分类回归。增加群聊与私聊隔离、好友摘要过滤、重复入站、过期审批、改稿后旧审批、外发响应丢失、重启恢复等用例。
- **阶段验收**重点覆盖四条交互：QQ 闲聊直接回复；查询当日作品或评论数据返回真实来源；主人审批后完成一次发布并核对作品；普通评论走专用流程，包含私密请求的样本只用公开范围处理。模型、权限及动作错误分别记录。
- **运行指标**先在现有看板增加单次链路视图。记录意图与实际路由、追问率、任务步骤耗时、重复动作数、待核验数、跨范围检索拒绝及验证成功率。首期上线门槛为固定回放和故障注入中零越权、零重复外部动作，已报告成功的外部步骤均有可复查证据。
- **切换顺序**先在脱敏库副本做备份和兼容测试，再旁路记录、对照路由、切换只读流量，最后在明确授权范围内验证带副作用的操作。每个事件只有一条可执行路径，真实 QQ、微信和抖音验收分别记录账号、环境和证据。
- **回退**按渠道切回旧路径，暂停新任务接单并保留追踪、草稿和任务数据。已发出或状态未知的动作先对账，禁止自动重放。现有 `scripts/data.mjs` 的备份对象是长期记忆库，P0-A 需要明确 Connect 和抖音库各自的快照与恢复方式，再在副本上演练三库恢复。

## 5. 本次请审阅的决定

| 决策 | 推荐方案 |
| --- | --- |
| 首期场景 | QQ 主人私聊先跑通「查数据 → 提案 → 审核 → 证据」，用桌面作为第二入口验证复用，抖音评论专用流程在 P1 切换。 |
| 私有记忆共享 | 主人通过已验证的账号绑定共享明确授权的记忆；好友、群聊和评论按原会话或公开范围读取。缺少范围来源的旧记录，默认仅供已验证主人在原有私有入口使用，审核后再开放跨渠道查询。 |
| 外部动作授权 | 首期保持现有两阶段发布审批，普通回复和批量互动沿用当前渠道的授权上限；扩大自动化范围与增加新渠道分别审阅。 |
| 人工核验 | 发布或回复缺少目标匹配的读回证据时显示待核验，看板保留账号、对象和尝试记录供人工确认。 |
| 任务迁移 | 首期从 `external_tasks` 演进统一执行，桌面生活任务和既有计划通过适配逐步接入。首条链路和第二入口通过后，再根据实际重复代码决定抽取和目录整理范围。 |

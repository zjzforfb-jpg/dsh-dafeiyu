# 大肥鱼长期记忆与检索优化计划

## 目标

让大肥鱼能够稳定回答“我以前说过什么、爸爸喜欢什么、最近发生了什么”，同时避免把群聊噪音、临时事件和未经确认的模型推断永久写入人格记忆。

核心原则：原始消息可回溯，长期事实可解释，检索结果可排序，冲突可以修正，删除可以验证。

## 当前基线

- `daily_memory_events` 保存跨渠道每日流水，默认保留30天。
- `memories` 保存明确要求记住的事实、偏好、共同经历和活动摘要。
- QQ、微信、桌面共用同一 SQLite 数据库，但群聊默认不写入私人长期记忆。
- 当前召回使用中文双字词、英文词、短语命中、可信度和时间新鲜度评分。
- 记忆库已记录 `access_count` 与 `last_accessed_at`，可用于后续检索评估和遗忘策略。

## 阶段计划

### M1：检索基线（已完成）

- 统一召回入口，保留旧调用兼容性。
- 加入可信度、短语命中、覆盖率和时间衰减。
- 增加过期字段、访问统计字段和数据库索引。
- 空查询不得返回记忆。
- 测试覆盖排序、空查询、访问计数和旧数据库迁移。

验收：相关记忆优先于仅仅“最近写入”的记忆；全套测试通过。

### M2：结构化事实层（下一阶段）

- 增加 `memory_facts`：主体、谓词、客体、来源、可信度、有效期和状态。
- 明确区分事实、偏好、关系、共同经历和临时事件。
- 每日摘要只生成“事实候选”，不能直接覆盖长期事实。
- 只有明确指令或高置信度候选进入长期事实层。

验收：同一事实不会因为不同渠道重复生成多条永久记忆。

### M3：冲突与版本管理

- 新事实与旧事实发生冲突时，建立 `supersedes_id` 链。
- 保留旧版本和修订理由，默认只向模型注入当前有效版本。
- 支持“更正、恢复、忘记”三类操作。
- 群聊事实不能自动覆盖爸爸私人事实。

验收：旧事实可审计但默认不召回；删除后不能再次进入上下文。

### M4：混合检索

- 结构化过滤：渠道、会话、隐私范围、记忆类型、有效期。
- SQLite FTS5：英文、数字和可分词文本的精确召回。
- 中文双字词索引：补足 FTS5 对中文短句的不足。
- 可选向量重排：只对关键词召回的候选集做 embedding，避免全库向量化。

验收：使用同义说法提问时，Top 5 结果至少包含正确记忆；无关记忆不超过1条。

### M5：遗忘、压缩和评估

- 每日流水保留30天，重要事件可延长保留。
- 低访问、低可信度的临时记忆逐步降权。
- 长期事实不自动删除，只能由规则或爸爸明确操作删除。
- 建立固定检索评测集，记录准确率、误召回率、延迟和上下文节省量。

验收：每次记忆算法修改都有离线回归结果，不能只凭主观感觉判断。

## 实现顺序与回滚点

1. 先完成数据库迁移和只读检索，不改变现有写入行为。
2. 再启用事实候选表，候选默认不进入模型上下文。
3. 通过评测集验证后，才开放高置信度事实自动升级。
4. 每个迁移前先执行 `npm run data:backup`。
5. 任一阶段失败时，可继续使用现有 `memories` 和 `daily_memory_events`，不会影响普通聊天。

## 禁止事项

- 不把模型一句“我会记住”当成写入成功凭证。
- 不把每日摘要全部永久注入上下文。
- 不让群聊内容自动成为爸爸的私人事实。
- 不用向量相似度替代来源、权限、时间和可信度判断。
- 不在没有评测数据的情况下自动提高长期记忆写入权限。

# 运行看板 · 页面规划（v2）

现状：6 个平铺 tab（首页/作品/评论/爆款/成长/活动），15 张卡片，卡片头、行高、meta 文案、分页各不相同；评论在「作品右栏」和「评论页」各出现一次，爆款和评论都属于「互动」却分家。

目标：像一台专业设备的控制台——**一屏看清在干什么，每张卡片长一个样，点进去有下一层**。

---

## 1. 信息架构（5 个一级导航）

| 一级 | 二级（页内分段） | 合并自 |
|---|---|---|
| **概览** | — | 首页 |
| **内容** | 作品库 ｜ 评论 | 作品 + 评论 |
| **互动** | 待回复 ｜ 爆款热评 | 评论 + 爆款 |
| **成长** | 课程 ｜ 档案 ｜ 毕业项目 | 成长 |
| **系统** | 时间线 ｜ 健康 ｜ 成本 | 活动 + 新增 |

规则：
- 一级导航 ≤5 个，固定顶栏；二级用 segmented control 放在内容区左上。
- 每条数据只有一个「家」，其他地方只做「入口 + 摘要」。
- 所有列表都带总数与分页；所有卡片都有空状态。

## 2. 各页模块与布局

### 概览（12 栅格：左 8 / 右 4）

```
┌ 预警条（有才出现，黄/红） ─────────────────────────────┐
├ 脉搏 4 卡：模型额度 · 今日任务 · 今日评论 · 粉丝       ┤
├──────────────────────────┬────────────────────────────┤
│ 待你确认（最高优先级）    │ 最近完成（分页 8）          │
│ 正在执行                  │                            │
│ 今日日程（时间轴）        │ 今日心情（卡）              │
│                          │ 快捷入口：写一条 / 查互动 / 学一课 │
└──────────────────────────┴────────────────────────────┘
```

- 待你确认排最上：有 1 条就高亮，>0 时导航上出红点。
- 日程用竖线时间轴：时间 · 动作 · 状态（done/skipped/等待确认）+ 跳过原因。
- 快捷入口是纯前端 POST 到已有接口（`/qq/send` 那类），调用动作走 `runAction`。

### 内容（三栏 300 / 1fr / 380）

```
┌ 作品库 ──────┬ 作品详情 ────────────┬ 评论 ──────────┐
│ 缩略图+标题  │ 封面 320px           │ 该作品评论      │
│ 编号 · 时间  │ 编号 · 主题 · 状态   │ 已回/未回 tag   │
│ 播放/赞 增量 │ 话题 pills           │                │
│ 评论 x/y     │ 设置 pills           │                │
│ 分页         │ 正文                 │ 分页            │
│              │ 趋势：7 日迷你折线    │                │
└──────────────┴──────────────────────┴────────────────┘
```

- 「评论」二级页 = 全库评论队列（按全部/未回复/已回复筛）。
- 作品详情新增**数据趋势卡**（`work_stats_history` 出 7 日折线：播放/赞/评论）。
- 存档作品统一灰化，排在最后，编号 `DFY-0000`。

### 互动（两段）

**待回复**：收件箱式队列，一行一条：作者 · 时间 · 原文 · 所属作品 · 我们准备回的话（可编辑，先只读）。
**爆款热评**：左视频列表（赞数 · 话题 · 热评数/已回数），右热评（作者 · 赞 · 正文 · 回复状态）。

- 顶部两个大数字：待回复 N · 今天已回 M。
- 回复按钮接 `--reply-inbox` 的单条能力（现有脚本加 `--only <id>` 即可）。

### 成长（沿用现有三段，统一卡片）

- 左：认证卡（Lv0–Lv4 + 升级要求进度条）、四阶段进度、课程列表（0–7 步）。
- 右：学习记录 / 成长档案（六类 + 理解等级）/ 毕业项目 12 格。
- 顶部 chip 显示 `学院 x/12`、当前等级。

### 系统（三段）

**时间线**：`agent_events` 分页，可按类型筛（任务/消息/动作/汇报/学习）。
**健康**：QQ 网关状态、服务启动时长、outbox 积压、最近崩溃（`connect-error.log` 尾部 3 条）。
**成本**：模型调用数、tokens（后端补）、语音次数、每日趋势 14 天。

底部固定：数据刷新时间 · 轮询 3s。

## 3. 组件规范（全站统一）

**卡片**：`border-radius:14px`，`padding:16px`，边框 1px `--line`，无阴影。
**卡片头**：高 40px，左标题 13px/600 + 计数灰字，右侧放筛选/每页条数；下边缘 1px 分隔线。
**行**：最小高 52px，两行：主文案 14px/500（超长省略），meta 12px `--dim`，字段顺序固定 `时间 · 来源 · 数值`。
**状态 tag**：胶囊 20px 高，四色（run 蓝 / wait 黄 / ok 绿 / bad 红 / dim 灰）。
**分页**：统一 `‹ 上一页 [1] [2] 下一页 › · 共 N 条 · 第 x/y 页 · 每页 8/16/32`。
**空状态**：一行灰字 + 一句建议（例：「还没有待回复的评论，等粉丝来。」）。
**加载**：骨架行 ×3，不闪白。
**错误**：卡片内红条「加载失败：原因」+ 重试按钮。

## 4. 视觉规范

- 栅格：最大宽 1600，页边距 24，卡片间距 20；12 列。
- 色板：`--bg #0a0d12` `--panel #11151d` `--line #1f2530` `--text #e8edf5` `--dim #8b96a8` `--blue #5b9cf8` `--ok #3fbf7f` `--warn #e8b23a` `--bad #ef5f5f`。
- 字号：页标题 20/600，卡片头 13/600，行主 14/500，meta 12/400，大数字 22/600（`font-variant-numeric: tabular-nums`）。
- 间距 token：4 / 8 / 12 / 16 / 20 / 24。
- 响应式：≥1200 三栏；900–1200 两栏；<900 单栏，导航收成下拉。

## 5. 实施顺序

| 步 | 内容 | 产出 |
|---|---|---|
| A | 顶栏 + 5 一级导航 + 二级 segmented + 统一卡片骨架（CSS token 一次写完） | 视觉统一的地基 |
| B | 概览重构 + 预警条 | 首页定稿 |
| C | 内容页（作品库/详情/评论 + 7 日趋势） | 内容定稿 |
| D | 互动页（待回复队列 + 爆款） | 互动定稿 |
| E | 系统页（时间线/健康/成本）+ P2 后端（预警计算、合规拦截表、token 用量） | P2 完成 |
| F | 视觉回归（CDP 截图 4 张 + 控制台 0 报错 + `npm test`） | 验收 |

## 6. 验收标准

1. 5 个一级页面，任意页面 3 秒轮询不闪、不跳滚动位置。
2. 所有卡片头/行高/meta/分页样式一致（截图比对）。
3. 每条数据只有一个来源页；重复入口只做跳转。
4. 新增 P2 数据（预警、合规拦截、tokens）都在系统页可见。
5. `npm test` 全绿，CDP 控制台 0 报错。

## 7. 模块化架构（新增模块只改一处）

目标：以后加「粉丝页」「周报页」「设置页」时，**只登记一次**，导航、路由、接口分页自动生效。

### 7.1 前端：模块注册表

```
connect/board/
  shell.mjs          # 顶栏 + 导航 + 轮询 + 路由（不知道具体有哪些模块）
  modules/
    home.mjs         # 概览
    content.mjs      # 内容（作品库 / 评论）
    interact.mjs     # 互动（待回复 / 爆款热评）
    growth.mjs       # 成长（课程 / 档案 / 毕业项目）
    system.mjs       # 系统（时间线 / 健康 / 成本）
  index.mjs          # 只做一件事：把模块塞进注册表
```

每个模块导出同样形状：

```js
export default {
  id: 'interact',
  title: '互动',
  icon: '💬',
  sections: [                    // 二级分段，没有就写 []
    { id: 'pending', title: '待回复', api: 'pending' },
    { id: 'hot', title: '爆款热评', api: 'hot' },
  ],
  snapshot: (snap) => [...],     // 概览用的摘要（可选）
  render(section, el, data),     // 画卡片
};
```

`index.mjs` 里一行一个模块：

```js
import home from './modules/home.mjs';
...
export const MODULES = [home, content, interact, growth, system];
```

**新增模块 = 新建 modules/x.mjs + 在 index.mjs 加一行。** 导航、hash 路由、轮询刷新、错误/空状态全部由 shell 统一处理。

### 7.2 后端：数据采集器注册表

```
connect/board/
  snapshot.mjs       # 汇总 status/pulse/mood/plan/fans/...
  sections.mjs       # 分页数据源注册表
  sections/
    works.mjs        # { key:'works', read(db,root,params) => {items,total} }
    comments.mjs
    hot.mjs
    timeline.mjs
```

`sections.mjs` 用 `Map` 注册：

```js
const SECTIONS = new Map([works, comments, hot, timeline, courses, ...].map((s) => [s.key, s]));
export const readSection = (key, db, root, params) => SECTIONS.get(key)?.read(db, root, params) ?? null;
```

`GET /api/board/list?section=x` 直接查表分发；**新增数据 = 新建 sections/x.mjs + 注册一行**，路由不用改。

### 7.3 约定（保证不互相踩）

- 模块只能读 `snap.*` 和 `GET /api/board/list`，不直接连数据库。
- 每个列表必须返回 `{items,total}`，分页由 shell 统一渲染。
- 新表迁移写在对应 `store.mjs`（抖音）或 `board/snapshot.mjs`（系统）里，带 `IF NOT EXISTS`。
- 所有时间统一 Asia/Shanghai 显示，接口里保留 ISO。

### 7.4 目录与文件规模上限

单文件 ≤ 400 行；超过就拆子模块。`board-page.mjs` 现在 600+ 行，这次拆分后变成 shell + 5 个模块文件。
